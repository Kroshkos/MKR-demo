## Сервис МКР.ВМедА: полный стек + подготовка к деплою на Amvera

Реализован полноценный сервис по ТЗ (контуры А и Б) с веб-кабинетами всех ролей и конфигурацией деплоя на Amvera Cloud.

### Что внутри
**Бэкенд** (`mkr-service/server`, Express 5 + better-sqlite3 + JWT httpOnly-cookie):
- Ядро расчёта по Приложению A ТЗ: `Балл = База × М × С × Кп × (команда?0.7:1)`; анти-паттерны (тезисы ≤5, одно мероприятие — один балл, окно 3 года, спорт ≤10).
- Схема БД из 10 таблиц ТЗ + сидирование (9 блоков, 6 профилей МПМК, отделы, коэффициенты, пороги 250/150, каталог, демо-пользователи по ролям).
- RBAC на 6 ролей, row-level доступ верификаторов (только свои блоки), журнал аудита.
- API: контур А (подача/верификация/пересчёт), контур Б (рейтинг, паспорт с радаром и ИУ/ИШ/Кг, решения Совета, дашборд, CSV), админ (коэффициенты, пороги, отделы, аудит).

**Фронтенд** (`mkr-service/client`, React 18 + Vite): 8 страниц — Вход, Мои достижения, Мой паспорт, Очередь верификации, Дашборд МКР, Сводный рейтинг (+паспорт резервиста, фиксация решений Совета), Настройки, Журнал аудита. SPA отдаётся сервером.

**Деплой на Amvera** (по docs.amvera.ru):
- `amvera.yml`: environment node / npm 20, multi-command build (установка зависимостей клиента + vite build), `containerPort: 3001`, `persistenceMount: /data`.
- SQLite сохраняется в постоянное хранилище `/data` в проде (данные переживают перезапуск контейнера).
- `Dockerfile` + `.dockerignore` — альтернативный путь через Docker-окружение.
- Bind на `0.0.0.0`, secure-cookie под HTTPS-прокси, секрет через env `JWT_SECRET`, флаг `SEED_DEMO=false` для чистого продакшена.

### Проверено
- ✅ `npm test` — все группы автотестов ядра проходят.
- ✅ Сквозной E2E по запущенному серверу: жизненный цикл заявки (подача → доработка → зачёт → пересчёт паспорта 271.9→303.4), решения Совета, CSV, воронка.
- ✅ RBAC: member → 403 на контур Б/верификацию; verifier → 403 на admin; sysadmin → 403 на контур Б; без токена → 401.
- ✅ Имитация конвейера Amvera: чистый git-clone → npm install (сборка клиента postinstall) → прод-запуск с /data → данные сохраняются между перезапусками.
